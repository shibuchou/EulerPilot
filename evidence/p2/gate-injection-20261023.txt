## 1. 为什么要造这个场景

上一轮消融的 `Dng vs D` 是 null，但**门从未 deny**（30 块 0 次），所以那不是"门没用"的证据。
这一步要造出让门真正拒绝的条件，并**先证明条件成立**（驱动里带前置断言），再谈其价值。

## 2. 造场景的过程（三次失败都记下来，因为每次暴露一条测量事实）

| 尝试 | 注入 | 结果 | 学到的 |
|---|---|---|---|
| ① 16–24 个等权重 CPU spinner，预算 10ms | p99 2.4–3.2ms | 门**没触发** | 服务确实被拖慢（goodput 59k→4–42k），但这个 1ms 周期探针的 p99 只抬到 ~3ms；10ms 预算够不着 |
| ② 预算改成 2ms（"静息 1.7ms ⇒ 2ms 是健康时可满足的预算"） | 24 spinner | 门先 deny 11–13 次，随后**在 1.71ms 的窗口上放行**并切换 | **门在噪声带里抖动**：预算落在测量噪声内时，它不是选择器，只是延迟器 |
| ③ 用唤醒风暴（96 个 1ms sleeper）代替 CPU 抢占 | 无 CPU 抢占 | p99 **降到 0.23ms**，goodput 满血（59999） | 静息时的 1.7ms 主要是 **idle 退出延迟**；把 CPU 顶醒反而让唤醒更快。"用静息值定预算"本身就是陷阱 |

## 3. 正式运行：4 轮 × (D, Dng)，顺序逐轮交替

每轮：基线 20s（**不交租约**，任何臂都不可能先动）→ 注入 16 个 spinner，静置 10s（让观测者吞下注入后的窗口）
→ 把租约交给 autopilot，**边测 45s** → 撤载并恢复 15s。
`D`：门控生效（floor 140 / wait 50 / p99 上限 **1ms**）；`Dng`：同参数但阈值永不可 bind。

## 4. 结论：行为成立，价值未测出

1. **门的"锁"行为被量化了**：Dng 在交接后**第 6 次轮询（≈12s）**就切换；D 一直拒绝，直到**第 26 次轮询（≈52s）**、
   即注入撤掉之后才放行。**门把动作推迟了约 40 秒**，期间 25 次拒绝全部有明确代码
   （`FOREGROUND_P99_EXCEEDED`）。
2. **它值不值，这一轮测不出来。** 注入期的 goodput 在同一臂内部就波动 **85–93%**
   （D 19.8k–51.1k，Dng 19.2k–53.5k），逐轮配对差为 −4.6%、−17.4%、+170.8%、−23.7%（中位 −11%）。
   这个方差来自"60k 负载 × 16 个 spinner"的平衡点本身是双稳的（在途从 1.7k 到 1.9k+ 抖动），
   n=4、45s 窗无法在这个状态里分辨一个百分级效应。**不得把 −11% 当中位数效应引用。**
3. **门是延迟器，不是否决器**：即使预算 1ms（低于健康服务也能达到的值），D 仍在注入撤掉后
   立刻放行并切换——因为探针的 p99 会时不时落回预算内。只要预算能被"碰巧达标"，
   门就只能推迟动作，无法阻止。

## 5. 三条测量事实（与协议 §5.1 同一条线，值得单独立项）

- **静息 p99 主要是 idle 退出延迟**：静息 1.7ms，而 96 个 1ms sleeper 把 CPU 顶醒后降到 0.23ms。
  因此"按静息值定预算"会把 idle 延迟误当成服务风险。
- **1ms 周期探针的 p99 对 CPU 抢占不敏感**：16 个 spinner 只把它抬到 2.5–4.3ms，而服务 goodput
  已经掉到 1/3——用它做前向 SLO 的在线判据，分辨率与"服务是否受伤"并不同步。
- **BG 进度在 CPU 争抢下反而升高**（163→176 单位/秒；只有把机器压到 goodput≈1k 时才降到 112），
  所以 `BG_PROGRESS_FLOOR` 在"CPU 争抢"这类伤害下不会响。

## 6. 这一轮不能声称的

- 不能声称"门有价值"或"门有害"。只能说：在预算是 1ms 的情况下，它把一次切换推迟了约 40s，
  而那次推迟对服务的影响**没有测出来**。
- 单机、单负载、n=4、45s 窗；注入强度与均衡点强相关，换强度结论会变。
- `Dng` 的阈值是"永不可 bind"（floor 0.001 / wait 10000 / ceil 60000），与"把门删掉"不完全等价，
  但本场景下两者行为相同（所有阈值都远不触发）。
- 驱动本身的三处自造缺陷已修复并留档：cgroup 读回 grep 了错子串、`max_foreground_p99_ms`
  写成浮点被 schema 拒绝（与上一轮同一类错误）、子 shell 里用 `$$` 而非 `$BASHPID`。
