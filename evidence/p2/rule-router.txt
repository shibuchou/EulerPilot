EulerPilot v2 — advisory rule router — SP3 evidence
Recorded 2026-10-21 on schedpilot-sp3 (<SP3-IP>)

Scope
  Deterministic advisory router over FeatureWindow. It NEVER writes the
  scheduler; policy.apply remains the only writer. This gives the Agent a
  read-only recommendation to test before adding auto-apply.

Rules (first match wins)
  insufficient CPU/load features              -> safe-basic, degraded
  PSI CPU some avg10 >= 20                    -> latency-balanced
  CPU >= 85 and PSI < 5                       -> throughput-balanced
  CPU <= 30                                   -> safe-basic (idle headroom)
  otherwise                                   -> latency-balanced
  PSI unavailable                             -> degraded; CPU >= 85 goes
                                                 throughput-balanced, else safe-basic

Hysteresis
  A new expert must persist for 5 s before it becomes current. Until then the
  decision reports pending=true and the previous expert.

Unit cases
  - all invalid -> safe-basic/degraded
  - psi=30      -> latency-balanced, switched
  - cpu=95, psi=1 -> throughput-balanced
  - min_route_ms=1000: t=0 pending, t=500 still safe-basic, t=1100 switched

Observed (integration_fd, 2 feature samples)

  With fewer than 3 samples the router conservatively degrades instead of
  guessing from a single CPU delta.
