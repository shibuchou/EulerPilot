## 4. 这些数字说明什么

1. **v2 的调度器在持续服务负载下确实有效，而且不是"倾斜"能解释的。** 固定 expert（C）比 A0
   的 goodput@5ms 高 +1.62%/+1.28%，20 块里 20/19 胜；p99 降 48%/32%、p99.9 从 16.4ms 降到
   8.6ms。关键对照是 **C vs A2 = +1.90%（20/0）**：静态 CPUWeight 的倾斜不但没带来收益，
   自身相对 A0 还是 −0.3%（CI 跨 0）；把 A2 当基线时 C 的优势比拿 A0 当基线更大。
   同时 **A2 的 BG 相对进度 ×0.999、C ×1.000、D ×1.001** —— 前台收益没有以 BG 饿死为代价。
2. **纯观测软件栈本身是有代价的，而且是负的**：A1（同等观测、mock 数据面、不挂载）比 A0
   低 −0.82% GET（CI 不含 0），p99 反而 +14.4%。这条是本项目以前从没量化过的成本项，
   它意味着"D 相对 A0 的收益"里有一部分要先还给观测栈自身。客户端 CPU 也从 0.63（A0/A1/A2）
   降到 0.37（C/D），说明挂载臂下服务响应更快、在途更少导致探针自身忙等更少——读数一致。
3. **自适应（D）没有超过固定 expert（C），并且 SET 上略差。** D vs C = −0.16%（GET，CI 跨 0，
   无法判定差异）与 −0.27%（SET，CI 不含 0，D 确实更差），p99 比 C 差 7.6–10.5%（14/6 负）。
   原因是可归因的：**每个块 D 都恰好发生 1 次切换**（20/20，`auto_switches` 列），
   即此前测得的 303–665ms 无策略空窗；`observations_rejected` 全为 0、没有 `adverse_experts`，
   所以不是门控把通道钉死，而是切换自身付了钱。**在这条负载上，自动切换的收益没有覆盖它自己的代价。**
4. **BG 保护在实测带宽附近**。BG 中位数 A0 164.63 / C 164.59 / D 164.43 单位/秒，
   BG 最长等待 A0 5.98ms、C 3.78ms（更好）、A1 8.22ms、A2 8.05ms、D 6.10ms。
   声明的 140 单位/秒下限与 50ms 等待上限在本轮从未触发——它们是护栏，不是本轮被检验的对象。

|---|---|---|---|---|

| D GET | +1.73% | **−0.00%** | +1.51% | +0.43% |

**这条必须写出来：收益集中在 5ms 以上的远尾，2ms 附近没有优势、甚至略负。**
直方图解释是 p95 处 C/D 与 A0 接近（2.05–2.88ms vs 2.23–2.32ms）而 p99/p99.9 显著更低，
所以 2ms 这条线附近两分布交叉——把 SLO 定在 2ms 就会得出"没有收益"的结论。
冻结时选 5ms 是标定阶段就存在的业务值，但正式汇报**四档同报**， headline 不得只挑对自己有利的阈值。

## 6. 范围与不能声称的

- **一台机器、一种负载、一种 SLO 设定、n=20 块。** 未做跨机、跨负载（noisy-mixed、
  phase-change、mixed-foreground）验证，协议 §7 要求的"独立机器/未见负载"这一条没满足。
- **不是四分类路由的效果。** 本轮运行时控制面只能声明 BACKGROUND 类，`class_map` 里没有
  LAT/CACHE 条目，所以 C/D 的收益全部来自 expert 档位的切片/预算参数作用在
  NORMAL→COMP 路径与 BG 上；`SP_DSQ_LAT / SP_DSQ_CACHE_* / SP_DSQ_SHARED` 在本轮未被喂。
  （**同日后续更新**：`spec.targets[].class` 已接入并做过存活压测，见
  `evidence/p1/class-route-20261023.txt`；但那不改变本表的意思——要主张四分类路由的收益，
  必须带 class 声明重跑矩阵。）
- **BG 结论是"未受损"，不是"被优化"**：相对进度 0.997–1.001，本轮没有构造饿死场景。
- **D 的每次切换都发生在块内**（`auto_switches=1`/块），故 D 的数字包含一段已量化的空窗；
  反过来本轮也不能证明"自适应永不划算"——负载形态、切换频率与预算设置都会改变结论。
- 超时 3 条全部计入（协议规定系统失败不从分母消失）；本轮没有任何块因"数字不好看"被剔除，
  `attempts.jsonl` 与 `dropped: none` 可核对。
- 工具层一处瑕疵：`analysis.txt` 里 `CHECK_RAW_REBUILDS_SUMMARY` 的文案打印成 `0.5%%`
  （格式串转义多余），只是文案，阈值确实是 0.5%；源码已修，重跑前的这份输出保留原样。
