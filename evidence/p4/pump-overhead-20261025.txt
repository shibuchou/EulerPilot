# R5 事件泵/BPF 自身开销量化(2026-10-25)

闭合 `events-link-20261025.txt` §5 的边界("泵/BPF 的 CPU 开销未量化")。
环境:SP3 冻结构建二进制(gen-2 executord,mock skill 消费端)。负载:redis 40k rps
开环(与旗舰同款探针)。脚本:`experiments/pump_overhead_sp3.sh`;原始件
`/root/epv2-evidence/pump-overhead-20261025/`。

## 1. 结果

| 量 | 值 |
|---|---|
| 泵进程 CPU(60s 负载窗) | **0.31s = 0.5% 单核**(utime+stime,/proc stat) |
| BPF 吞吐(同窗) | **726,919 次 wakeup 追踪 / 723,525 次等待计数**(≈12.1k 事件/s);pid 复用丢弃 0、聚合丢失 0 |
| 服务影响(配对,泵关 vs 开,n=6) | goodput@5ms 中位差 **−0.010%**,范围 [−0.049, +0.592] |
| 同上,p99 | 中位 +10.4%,范围 [−27.4, +124.1]——落在已知的 p99 窗间噪声带(协议 §5.1:CV 3.8–20%),**不可归因**于泵 |
| 执行服务摄取 | 59 observations accepted / 0 rejected(全程) |

## 2. 读法

- 泵的开销结构上界清楚:**0.5% 单核 + 每 2s 一次 socket 上报**;在 12k 事件/s 的
  真实流量下计数器零丢弃,说明当前形态没有隐藏的溢出路径。
- 对服务的 goodput 影响在配对分辨率为零;p99 侧的表观波动与已测噪声同量级,
  本实验**不声称**泵对 p99 无影响,只声称"分辨不出"(与协议 §5.1 的分辨率纪律
  一致)。
- 注意对照边界:本实验泵用 2s 窗口;在线门控的 15s 窗(§5.1)下 CPU 只会更低
  (聚合频率不变、窗口更长)。

边界:单机;40k rps 一档负载;泵为 print+socket 双输出模式(仅 print 会更低);
无 PMU 对照。执行服务侧的 ingest 计入 mock skill 消费端(真实 cgroup 域消费路径
的额外成本是每窗一次 JSON 解析,量级远小于泵本身)。
