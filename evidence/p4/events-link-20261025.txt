
## 3. 真机时间线(tests/integration_events.sh,2026-10-25 16:30 UTC+8)

被看对象:systemd scope(CPUWeight=100)→ cpu.weight=100;噪声:独立 cgroup
8 个纯自旋海绵;信号:被看 cgroup 16 个 50ms 周期 sleeper(每次唤醒都要在饱和
CPU 后面排队)。arm:threshold 5ms、sustain=release=1、min_interval 1s、
policy_ttl 12s、action cpu.weight=5000。泵窗口 3s/间隔 0.5s。

| 相位 | 断言 | 结果 |
|---|---|---|
| A 空载 | 8s 内不动(weight=100),hold 为 below-threshold 类 | PASS |
| B 饥饿 | weight 100→5000(守卫日志 "event guard applied cpu.weight=5000") | PASS(16:30:26) |
| C 撤载 | weight 5000→100("event guard rolled back") | PASS(16:30:30) |
| D 杀泵 | 重新饥饿→再次 5000;kill 泵后 25s 内 TTL 兜底回 100;hold=EVENT_OBSERVATION_STALE 且 stale_checks≥1;不再重试 | PASS |
| E 泵单独 | 无执行服务时泵跑 7s,weight 保持 100(泵非写者) | PASS |

回归:unit(550 断言,含事件链 5 个测试组)全过;`ctest` **8/8**(integration_events
为第 8 项,总 90s);`validate_design.py` 6 正例/27 反例。

## 4. 过程中钉死的三个事实(不写下来就会重踩)

1. **raw tracepoint 的名字不带 category**:`SEC("raw_tp/sched_wakeup")` 才能附着,
   `raw_tp/sched/sched_wakeup` 报 ENOENT;经典 `tp/` 前缀下 BPF_PROG 宏取参会被
   verifier 拒(reg type unsupported for arg#0)。
2. **本机 cgroup 根和 system.slice 默认只委派 memory pids**:裸 mkdir 出来的目录
   没有 cpu.weight(打开报 EACCES,不是 ENOENT)。systemd 只在单元声明 CPUWeight
   时按需启用 +cpu——所以测试必须用 `systemd-run -p CPUWeight` 建 scope,不能
   裸 mkdir。
3. **纯自旋任务几乎不产生 wakeup 事件**:信号是"wakeup→首次运行的等待",自旋者
   只在 fork 时有一次 sched_wakeup_new;要制造可测的 runnable 等待,被看组必须
   周期性睡眠再唤醒(噪声组才用自旋海绵)。

另修一个产品缺陷:观测/武备路径校验原本拒绝 cgroup 根本身("/sys/fs/cgroup"),
而根是合法的观测对象——已放行(策略效果路径校验保持更严)。

## 5. 边界(本证据不证明什么)

- **不含任何性能结论**:泵/BPF 的 CPU 开销、事件量上限(map 4096 个 cgroup、
  热点 cgroup 聚合串行化)未量化;`agg_updates_lost` 计数器在位但本轮为 0。
- **测量的语义近似**:wait = "最后一次 wakeup 到首次运行"(延迟记账同款近似),
  不是完整排队驻留时间;已在 BPF 源码头注释声明。
- **watch 按 path 匹配**:同名 cgroup 删除重建后路径继续匹配但身份(kernfs id)
  变化未被拒绝——与 TargetBinding 的"重建即失效"纪律相比是缺口,记 P4 待办;
  构造:重建后 id 不同、观测按新 id 上报、执行服务按 path 匹配仍会动作。
- **cgroup 域没有"已有效应时再 apply"的通用保护**(既有边界,本轮未改):
  事件守卫自查 active_(别人的效应在位时 hold),但人工 apply 与武装守卫并发
  时仍靠操作纪律。
- 真机 PID 复用由 start_time 比对丢弃(计数器),未构造复用场景实测。
- 本轮 ctest/integration 之外未重跑:验收六轮、fail-safe 矩阵、旗舰矩阵
  (见 IMPLEMENTATION_PLAN 重跑义务)。
