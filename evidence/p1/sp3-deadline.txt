Recorded 2026-10-21 on schedpilot-sp3 (<SP3-IP>)

Gap
  The request deadline was checked only when the request entered. A slow
  skill.apply could finish and commit after the caller's deadline.

Change
  handle_apply now checks now_epoch_ms() against envelope.deadline:
    - after target revalidation, before PREPARED;
    - after skill.apply, before VERIFIED;
    - after skill.verify, before VERIFIED/COMMITTED.
  If the deadline passed after a successful apply, the executor uses the
  normal compensation path with ErrorCode::kDeadlineExceeded; it does not
  commit. rollback is intentionally allowed to finish even if its deadline
  passed, because safety restoration must not be aborted mid-way.

Test
  SlowMockSkill sleeps 300 ms in apply; the envelope deadline is now+100 ms.
  Response is not VERIFIED, error code is DEADLINE_EXCEEDED, and the mock
  value is restored to the pre-apply state.
