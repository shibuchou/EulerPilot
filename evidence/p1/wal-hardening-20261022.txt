EulerPilot v2 — WAL recovery hardening — SP3 evidence
Recorded 2026-10-22 on schedpilot-sp3 (<SP3-IP>)

Changes
  - Journal::append no longer advances seq before success. A write/fsync failure
    marks the journal broken, rewinds the file to the last complete record and
    refuses further appends until restart/reconcile.
  - Executor tracks the active effect immediately after skill.apply succeeds,
    before VERIFYING/COMMITTED/state persistence. A state.json persist failure
    can no longer lose the recovery context.
  - Compensation and explicit rollback clear active only after rollback and
    post-rollback verification succeed.
  - WAL failure paths still perform the restricted emergency detach. If the
    effect is restored but the audit record cannot be written, the response is
    DEGRADED / AUDIT_PENDING, not a false ROLLED_BACK.
  - auto_fallback keeps active until the effect is verified gone; a failed
    rollback/verify is retried with a 2s backoff, and a broken WAL no longer
    skips the detach.
  - New apply requests are refused with RECOVERY_REQUIRED while the journal is
    broken.

Unit fault matrix (test-only Journal fault injection)
  PREPARED append fails            -> no effect, journal broken, next apply refused
  VERIFYING append fails after effect -> effect rolled back, DEGRADED/AUDIT_PENDING
  ROLLBACK_PREPARED append fails   -> effect detached, DEGRADED/AUDIT_PENDING
  ROLLED_BACK append fails         -> effect detached, DEGRADED/AUDIT_PENDING
  Journal reopen after a failed append -> prior records intact, appends work
