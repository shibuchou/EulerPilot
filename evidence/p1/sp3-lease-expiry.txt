EulerPilot v2 — lease-expiry auto fallback — SP3 evidence
Recorded 2026-10-21 on schedpilot-sp3 (<SP3-IP>)

Gap
  Before this change, lease expiry was only checked when a request arrived.
  An attached scheduler kept running after its lease expired.

Change
  Executor starts a monitor thread (500 ms period). If an active applied
  action exists and ownership_.lease().expires_ms has passed, it performs an
  automatic rollback while holding the executor mutex:
    ROLLBACK_PREPARED (reason=lease expired) ->
    skill.rollback -> verify_rolled_back ->
    ROLLED_BACK + generation advance
  The scheduler returns to fair, pins/runtime are removed, degraded_ is set,
  and status reports last_fallback="lease expired".
  A failure in this path journals RECOVERY_REQUIRED and keeps degraded set.
