## 1. 文档背景

EulerPilot v2 是运行在 openEuler 24.03 LTS-SP3 上的资源管控 Agent(赛题 proj2)。
部署工作包括:准备一台满足内核与 cgroup 要求的机器、放置冻结二进制或从源码重建、
按层验证(契约 → 单元 → 内核集成 → 一键验收 → 故障矩阵 → 演示)。

阅读路径:已拿到交付镜像 → 第 3、4、6 章;从源码构建 → 第 3、5、6 章;要改内核
或换机器 → 第 5.2 节陷阱 + 第 8 章运行注意。

## 4. 形态一:从交付镜像部署

### 4.1 导入与启动

```bash
# 宿主机:校验包
cd /home/ubuntu/sp3-vm/deliverable-20261025 && sha256sum -c SHA256SUMS

# 定义并启动域
virsh define domain.xml
virsh start schedpilot-sp3
virsh domstate schedpilot-sp3          # 期望 running

# 进入客户机
ssh root@<SP3-IP>
```

### 4.2 首启两项检查

```bash
uname -r                          # 期望 6.6.0-schedpilot-sp3
cat /sys/kernel/sched_ext/state   # 期望 disabled
```

任一项不符即停止部署:内核不对则 sched_ext 不存在;`state` 非 disabled 说明已有
调度器在位(可能是残留的参考实现),须由其属主回退。

```bash
ls -l /sys/kernel/sched_ext/      # state / ops / scheduler_enable_seq 等接口
python3 /root/epv2-src/scripts/doctor.py
```

镜像内二进制与源码树已就位,直接跳到第 6 章验证。

## 5. 形态二:从源码构建

### 5.1 构建顺序

```bash
cd /root/epv2-src
# ① BPF 对象(调度器 + 事件 tracing;参数:SRC OUT sched|events|all)
bash scripts/build_bpf_sp3.sh /root/epv2-src /root/epv2-src all
#    输出 .bpf.o 与 skeleton 的 SHA256,须记入 PROVENANCE

# ② 全量构建(第二条参数是硬要求,见 5.2 陷阱一)
cmake -S /root/epv2-src -B /root/epv2-build \
  -DEP_LIBBPF_STATIC=/root/ep-sched-build/build/obj/libbpf/libbpf.a
cmake --build /root/epv2-build -j"$(nproc)"
```

表 8 构建目标

| 目标 | 类型 | 说明 |
|---|---|---|
| `ep_core` | 静态库 | 核心逻辑 + 执行服务 + Skill + mock |
| `ep-executord` | 可执行 | 执行服务 |
| `ep` | 可执行 | CLI 客户端 |
| `ep-sched-loader` | 可执行(条件) | BPF 调度器加载器 |
| `ep-schedctl` | 可执行(条件) | cfg/class 辅助 |
| `ep-evtmon` | 可执行(条件) | 事件观测泵 |
| `ep_unit_tests` | 可执行 + CTest | 单元测试 |

表 9 CMake 选项

| 选项 | 值 | 后果 |
|---|---|---|
| `-DEP_LIBBPF_STATIC=<path>/libbpf.a` | 内核树静态库路径 | 不加则 loader 链接系统 `libbpf.so`,启动即静默退出 |
| `-DEP_SCHED_LOADER=<path>` | SchedPilot 参考 loader 路径 | 仅用于真内核对照测试;不设时集成测试用本仓库构建出的 loader |

构建系统对回退到动态 libbpf 会打印 WARNING——**看到该警告即视为构建不合格**,
必须重配。

### 5.2 构建与部署陷阱(全部实测)

表 10 陷阱清单

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| 1 | loader 启动即退出、日志为空,4 个 sched 系测试挂 | 链接了系统 `libbpf.so`;必须用内核树静态库 | 加 `-DEP_LIBBPF_STATIC=…`;CMake 已加 WARNING;第一次干净构建即踩此坑 |
| 2 | 骨架重复构建后 skeleton 报错 | bpftool < 7.3 不支持 struct_ops 骨架生成 | 使用 `/root/ep-sched-build/build/sbin/bpftool`(7.3) |
| 3 | 新建 cgroup 写 `cpu.weight` 报 Permission denied | 本机根与 `system.slice` 默认只委派 `memory pids` | 测试用 `systemd-run --scope -p CPUWeight=100 --unit X` 创建 scope;或在委派列表加 `cpu` |
| 4 | `validate_design.py` 报缺模块 | python3 无 jsonschema | `python3 -m pip install jsonschema`(仅设计层需要) |
| 5 | 分发后脚本不可执行 | `git archive`/压缩包丢失执行位 | `chmod +x scripts/*.sh experiments/*.sh tests/*.sh` |
| 6 | 集成测试大量 SKIP(退出码 77) | 非 root / 无 sched_ext / 非 cgroup2fs / pin 非空 | 在 SP3 上以 root 运行并清理残留;验收层把 SKIP 判为失败 |
| 7 | 长时间实验被 SSH 断开杀死 | 子进程未脱离会话 | 统一 `setsid nohup … < /dev/null &`,日志落盘,结束判定看 marker |

### 5.3 源码同步纪律

远端同步前必须检查路径、`git status`/`git diff`、实际生效文件与备份;用暂存目录
对比,避免覆盖未同步改动。Windows 侧文本在上传前统一转 LF,Python 命令用 `python`
而非 `python3`(视目标机而定)。构建与实验通过锁文件互斥:

```
/run/lock/eulerpilot-v2-acceptance.lock   一键验收
/run/lock/eulerpilot-v2-matrix.lock       性能矩阵
/run/lock/eulerpilot-v2-fault.lock        故障矩阵
```

## 6. 部署验证

按层执行,任一层不通过即停止后续。

```bash

bash /root/epv2-src/scripts/verify_package_sp3.sh /root/epv2-build /root/epv2-src
#    期望末行:PACKAGE_VERIFY: all checks passed

#    期望:8/8 通过,0 SKIP
```

## 7. 升级与回滚

表 12 三类升级

| 对象 | 步骤 | 必须重跑 |
|---|---|---|
| 二进制 | 更新源码 → 5.1 重建 → 第 6 章 ①③④ | 影响控制面行为的变更之后,**受影响的性能矩阵必须在新构建上重跑**(项目纪律) |
| 镜像 | 停机 → `qemu-img convert` → 更新 `SHA256SUMS` | 包校验 + 演示 |
| 内核 | 保留原 GRUB 条目 → 安装新内核 → 重启 → 4.2 检查 | 全部六层 |

回滚路径:

- **二进制回滚**:保留上一代构建目录副本,切回后重跑第 6 章 ①③;
- **镜像回滚**:保留交付 qcow2 副本,替换后 `virsh start` 即可;运行时状态目录
  `/run/eulerpilot-v2` 随重启清空;
- **内核回滚**:GRUB 菜单保留原 openEuler 内核条目;`psi=1
  systemd.unified_cgroup_hierarchy=1` 仅作用于自编译内核的引导项;
- **在位调度器**:任何回滚前先确认 `state=disabled`;异常残留的 pin 由同实例重启
  执行服务回收(见 8.2)。

## 8. 运行注意事项

1. **互斥**:参考调度器 `schedpilotd` 与本系统不能同时运行(Linux 同时只允许一个
   sched_ext 调度器,第二次注册返回 EBUSY)。对照实验必须串行执行。
2. **pin 生命周期**:调度域服务停止时自动回退并清理自己的 pin(SIGKILL 与崩溃时
   由同实例重启回收;**更换状态目录后无人回收**,需人工确认无调度器在位再清理)。
3. **磁盘**:实验生成的逐请求原始件(一次旗舰矩阵约 5.8GB)留在
   `/root/epv2-evidence/`,仓库只入库汇总、`comparisons.csv` 与 SHA256SUMS。状态
   目录所在盘写满时,执行服务仍能完成拆除、但拒绝建立新效应(`store_warning`)。
4. **长任务**:统一 `setsid nohup … < /dev/null &` 启动,日志落盘;结束判定看
   marker 文件;进程清理按记录的 PID 操作,不用模式匹配杀进程。
5. **一次旗舰矩阵约 3.7 小时**,期间不要并发跑验收或故障矩阵(锁文件互斥)。
6. **时间戳**:证据文件名带日期,同日多次运行须区分(如 run4/run6/run8),失败轮
   与作废轮全部保留,不得覆盖。
