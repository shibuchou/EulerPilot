## 1. 文档背景

EulerPilot v2 是运行在 openEuler 24.03 LTS-SP3 上的资源管控 Agent(赛题
proj2)。它依赖自编译的 sched_ext 内核、BPF 工具链和一组冻结的二进制产物,
部署正确性直接决定验收与实验结论的有效性:同一份源码用不同链接方式构建出的
loader,行为可能完全不同。本手册给出两种部署形态——交付镜像直接启动、源码
完整重建——并给出部署后的验证步骤与三个实测踩过的构建陷阱。

阅读路径:已拿到交付镜像 → 第 3、4 章;从源码构建 → 第 5 章;两种形态都以
第 6 章验证收尾。主机名与 IP 为占位写法(`<SP3-IP>`),按实际环境替换。

## 4. 从镜像部署

```bash
# 宿主机
virsh define domain.xml
virsh start schedpilot-sp3
# 客户机起后(SSH 见 domain.xml 接口约定)
ssh root@<SP3-IP>
```

启动后先做两件事:

```bash
uname -r                      # 期望 6.6.0-schedpilot-sp3
cat /sys/kernel/sched_ext/state   # 期望 disabled(idle)
```

镜像内二进制与源码树已就位,直接跳到第 6 章验证。

## 5. 从源码构建

### 5.1 构建顺序

```bash
cd /root/epv2-src
# ① BPF 对象(调度器 + 事件 tracing;参数:src out sched|events|all)
bash scripts/build_bpf_sp3.sh /root/epv2-src /root/epv2-src/sched all
# ② 全量构建
cmake -S /root/epv2-src -B /root/epv2-build \
  -DEP_LIBBPF_STATIC=/root/ep-sched-build/build/obj/libbpf/libbpf.a
cmake --build /root/epv2-build -j"$(nproc)"
```

`build_bpf_sp3.sh` 输出 object 与 skeleton 的 SHA256,记入 PROVENANCE。
其余环境变量(KSRC/VMLINUX_DIR/BPFTOOL)在脚本头部,按实际路径覆盖。

### 5.2 构建陷阱(全部实测)

表 4 构建陷阱

| 现象 | 原因 | 处置 |
|---|---|---|
| loader 启动即退出、日志为空 | 链接了系统 libbpf.so;内核树静态库必须显式指定 | 加 `-DEP_LIBBPF_STATIC=…`;CMake 会对回退链接打 WARNING |
| 骨架重复构建后 skeleton 报错 | bpftool < 7.3 不支持 struct_ops 骨架 | 使用 `/root/ep-sched-build/build/sbin/bpftool`(7.3) |
| 新建 cgroup 写 cpu.weight 报 Permission denied | 本机根与 system.slice 默认只委派 memory/pids | 测试用 `systemd-run --scope -p CPUWeight=100 --unit X` 创建 scope |

### 5.3 脚本执行位

脚本执行位由 git 跟踪。经 `git archive` 或压缩包分发时,如需手动补:
`chmod +x scripts/*.sh experiments/*.sh tests/*.sh`。

## 6. 部署验证

```bash
# ① 包校验:二进制哈希 + 证据文件 + 契约三查
bash scripts/verify_package_sp3.sh /root/epv2-build /root/epv2-src
# 期望末行:PACKAGE_VERIFY: all checks passed

# ② 测试(8 项集成必测,含真内核挂载与事件链)
cd /root/epv2-build && ctest --output-on-failure

# ③ 一键验收(可选,六轮)
bash /root/epv2-src/scripts/accept_sp3_rounds.sh verify1 /root/epv2-build /root/epv2-src 6

# ④ 故障矩阵(可选,17 条目)
bash /root/epv2-src/experiments/fail_safe_matrix_sp3.sh \
  /root/epv2-build/ep-executord /root/epv2-build/ep /root/epv2-build/ep-sched-loader \
  /root/epv2-evidence/fail-safe-$(date +%Y%m%d)
```

前置:idle 检查(第 4 章两条)不满足时,测试按设计 SKIP(退出码 77)。

## 7. 升级与回滚

- **二进制升级**:源码更新后按第 5 章重建,重复第 6 章验证。影响控制面行为的
  变更之后,性能矩阵需在新构建上重跑(项目纪律,见 `docs/测试文档.md` §8)。
- **镜像回滚**:保留交付 qcow2 副本,替换后 `virsh start` 即可;镜像内状态目录
  `/run/eulerpilot-v2` 为运行时产物,随重启清空。
- **内核回滚**:GRUB 菜单保留原 openEuler 内核条目;`psi=1
  systemd.unified_cgroup_hierarchy=1` 参数仅作用于自编译内核的引导项。

## 8. 运行注意事项

1. 参考调度器 `schedpilotd` 与本系统互斥(Linux 同时只允许一个 sched_ext
   调度器);同时只能运行其一。
2. 调度域服务停止时自动回退并清理自己的 pin;异常退出留下的 pin 由同实例
   重启回收,状态目录更换后无人回收。
3. 实验脚本生成的逐请求原始件(GB 级)保留在 `/root/epv2-evidence/`,仓库只
   入库汇总与 SHA256SUMS;磁盘紧张时按目录归档。
4. 长任务统一 `setsid nohup … < /dev/null &` 启动,日志落盘;结束判定看
   marker 文件,进程清理按记录的 PID 操作。
