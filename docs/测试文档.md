## 1. 文档背景

EulerPilot v2 管理的是内核调度器与 cgroup 资源,测试要回答的问题比"功能对不对"
多一层:策略生效之后,内核里的状态是否真的与声称一致;进程崩溃、磁盘写满、外部
越权修改之后,系统是否仍能回到安全状态。为此测试体系按层设计——设计契约、单元、
内核集成、一键验收、故障恢复、性能——每层有明确的通过标准,能力缺失时记录
UNSUPPORTED 或 SKIP,与 PASS 并列呈现。

本文记录各层的范围、方法与结果。逐项证据文件在 `evidence/` 目录,每个文件含
完整性与边界章节;实验方法的预注册协议见 `docs/EXPERIMENT_PROTOCOL.md`。

## 3. 单元测试

587 个断言覆盖:

- 策略校验真值表(SchedulingPolicy/CgroupPolicy/EventArm 的字段、范围、枚举、
  未知字段、路径穿越、class⇔role 一致性);
- 事件判定函数(持续/回落滞回、证据门、WATCH_REBUILT、身份匹配);
- 事务状态机(WAL 顺序、幂等重放、同键异容拒绝、世代号冲突);
- 目标绑定生命周期(pidfd 持有、cgroup 重建失效、成员迁出撤销);
- 门控矩阵(服务半区、绝对上限、分辨率护栏跳过、观测断供)。

运行:`cd <build> && ctest -R unit`。单元层不需要 root 与 sched_ext。

## 4. 内核集成测试(8 项必测)

表 2 集成测试清单

| 测试 | 覆盖 | 关键断言 |
|---|---|---|
| integration | 执行服务基本事务 | apply→verify→rollback 全链,幂等重放 |
| integration_sched | sched-ref 模式挂载 | 子进程 loader 生命周期、崩溃回收 |
| integration_fd | FD 传递生产路径 | link fd CLOEXEC、ops=eulerpilot、class 从内核 map 读回 |
| integration_lease | 租约互斥 | 异属主拒绝、租约到期自动回退 |
| integration_ttl | 策略 TTL | 到期自动回退、无 pin 残留 |
| integration_cgroup | cgroup 域 | 写读回、漂移纠正、崩溃 marker 恢复、跨域拒绝 |
| integration_events | 事件链六相 | 见下 |
| unit | 单元测试 | 同步执行,失败即整体失败 |

事件链六相(一项测试内的连续时间线):空载不动 → 饥饿升权(100→5000)→
撤载补偿 → 杀泵后门冻结(STALE)且 TTL 兜底 → 同路径 cgroup 重建触发
WATCH_REBUILT 且拒绝动作 → 泵单独运行对被看目录零写入。

前置条件不满足(非 root、无 sched_ext、pin 非空)时按设计 SKIP(77),验收层
将 SKIP 判为失败,防止跳过被当成通过。

## 5. 一键验收

`accept_sp3_rounds.sh <标签> <build> <src> <轮数>` 每轮执行:环境 idle 断言 →
ctest 八项(严格校验器拒绝任何 SKIP/缺失)→ A/B/C 三臂 liveness → 产物与源码
哈希 → 收尾状态断言。累计记录:r28、r29、r30 各六轮全部 rc=0,对应三代构建。

## 6. 故障恢复矩阵

表 3 fail-safe 17 条目(run9/run10/run11 均 17/17)

| 条目 | 场景 |
|---|---|
| S01/S02 | class/basic 两模式挂载后故障回退,残余由内核 map 自证清除 |
| S03 | adaptive 模式在 apply 阶段被拒(设计上未启用,拒绝即其 fail-safe 形态) |
| S04/S05 | 挂载中 SIGKILL 执行服务 / loader |
| S06/S07 | 租约到期 / 策略 TTL 到期 |
| S08/S09 | 无效策略(未知字段、非法 class)、越界与类型错误 |
| S10/S11 | 裸请求世代号冲突 / 第二实例启动 |
| S12 | 外部越权改 cfg 与 class(改值、删除均被轮换抽样纠正) |
| S13 | cgroup 成员迁出(撤销读回确认) |
| S14 | 状态目录灌满(ENOSPC;仅内存租约完成拆除,新效应被拒) |
| S15 | CPU 热插拔(本内核行为为注销调度器;系统检出并补偿) |
| S16 | 无法在 v2 构造的场景如实标注 |
| S17 | 两步写入的第二步失败(补偿成功、世代号不推进、可干净重试) |

每条断言:目标进程继续推进、无本场景新增 pin、state 归位。失败轮的原始现场
保留(`-run4/` 目录为历史失败样例)。

## 7. 性能测试

### 7.1 方法

预注册协议(`experiments/flagship_params.json`):Redis 开环负载(固定到达率,
服务变慢时压力不降)、块内配对(同块内各臂共享初始化)、配对 block bootstrap
10000 次给 95% CI、goodput@SLO 按逐请求原始数据统计。无效规则预注册;低吞吐
与高方差不构成剔除理由。

### 7.2 结果(20 block,冻结构建)

表 4 主对照

| 对照 | goodput@5ms | 胜/负 | p99 |
|---|---|---|---|
| C(固定专家)vs A0(默认 fair) | GET +1.83% [1.38,2.26] / SET +1.39% | 20/0、18/2 | −39.6%/−32.8% |
| C vs A2(静态 cgroup 倾斜) | +1.90% | 20/0 | 收益超出静态倾斜 |
| D(自适应)vs A0 | +1.74% / +1.05% | 19/1 | −37.9% |
| A1(纯观测栈)vs A0 | −0.55~−0.82% | — | 观测栈成本,如实披露 |
| B(BASIC 数据面)vs A0 | +1.75% [1.45,2.09] | 10/0 | −40.8% |
| E(参考 schedpilotd)vs A0 | GET +1.92%;SET 打平 | 10/0 | −49.4% |
| BG 相对进度 | 0.998–1.006 | — | 后台未受损 |

消融结论:A1→B→C 的增量链与 class-routing 零结果、mixed-foreground 的
Dnc=D(联合 SLO 2/3)共同表明,该负载上的收益来自数据面切片/预算形态,class
声明提供的是可审计的契约。

### 7.3 敏感性与边界

- 阈值敏感性同报:@1ms C GET +2.5%;@2ms 各臂无优势甚至略负;收益集中在
  5ms 以上远尾。
- D vs C 在重跑构建上统计打平(点估计 −0.19%/−0.39%,CI 跨 0)。
- 范围:单机、单负载、单 SLO 设定;跨机为 UNSUPPORTED(备用机为 cgroup v1
  且无 PSI);X 臂(上游 scx 对照)为 UNSUPPORTED(上游主线 Rust 化且目标
  内核高于本机)。

## 8. 测试环境与数据管理

- 环境指纹:每轮验收与矩阵记录内核、构建哈希、臂序(种子驱动)、负载参数;
  manifest 含 tested_code_commit 与产物 SHA256。
- 原始数据:逐请求延迟(8 字节定长记录)留在测试机 `/root/epv2-evidence/`,
  仓库入库汇总、comparisons.csv 与 SHA256SUMS;汇总数字可由原始件重算
  (校验项 CHECK_RAW_REBUILDS_SUMMARY,偏差 ≤0.5%)。
- 纪律:正式构建之后受影响的矩阵必须重跑;失败轮与作废轮全部保留;性能运行
  与故障注入分开执行。

## 9. 已知限制

- adaptive 模式、心跳降级、PMU 分类三项未启用(UNSUPPORTED by design)。
- 事件 watch 按 path 与 kernfs id 匹配;cgroup 重建使授权失效,需重新武装。
- BPF 聚合 map 上限 4096 个 cgroup;饱和场景未构造。
- 性能结论限定于第 7.3 节条件。
