## 2. 方案（架构与契约）

一句话：**用户态 Agent 负责感知与决策，特权执行服务是唯一写者，v2 自建 sched_ext 数据面执行；
所有决策被声明式契约约束，失败时向"无策略"方向回退。**

三层，权限单向递减（`design/INTERFACES.md`）：

1. **决策层（Agent/规则）**：FeatureWindow（CPU/load/PSI 窗口，带 valid/age/missing）→
   规则分类与路由 → SLO 门控 → AutoPilot。默认 **advisory**，自动 apply 默认关闭。
2. **执行服务 `ep-executord`（唯一特权写者）**：lease/fence + generation + append-only WAL +
   事务状态机（PREPARED→APPLYING→VERIFYING→VERIFIED→COMMITTED，失败走 COMPENSATING→
   ROLLED_BACK 或 RECOVERY_REQUIRED+degraded）+ 幂等 + Unix socket（`SO_PEERCRED` 校验 uid）。
   它启动时取 `flock` 独占状态目录，第二实例启动失败。
3. **数据面**：v2 自建 loader（`eulerpilot` ops，每实例 pin `/sys/fs/bpf/eulerpilot-v2/<instance>`）。
   `sched` 模式：loader 一次性 attach 后经 SCM_RIGHTS 把 **link FD 交给执行服务**并退出（生产路径）；
   `sched-ref`：子进程 loader + PDEATHSIG（对照）。cfg 参数由短命 `ep-schedctl` 写入并回读。

效果域有两个：`sched`（切片/预算/class_map/抢占）与 `cgroup`（`cpu.weight`）。
策略文档有两类，**kind 必须与实例的 skill 域一致**，不匹配 `UNSUPPORTED` 拒绝且零副作用。

关键设计决定（都有理由，不是风格）：

- 生成策略**限于声明式白名单**，不生成/在线编译任意内核代码。
- **BG 是业务角色，LAT/COMPUTE/CACHE 是运行特征**；禁止把陌生的高 CPU 任务自动降为 BG。
  结构约束：`class=BG` ⇔ `role=BACKGROUND`。
- 判定顺序是契约：**权限 → 证据 → 抑制**（dwell / 候选保持 / 冷却 / 切换预算）。
  失败的动作照样消耗预算（回滚已经真的撕开一段空窗）。
- **fail-safe 方向不对称**：拆掉已有效应永远允许（回到 default fair 是安全侧），
  建立新效应必须有可持久化的审计。状态目录写不下去时就是这样处理的（见 §3.4）。
- 比较类判定要先声明分辨率：策略要求的敏感度若不大于实测窗间噪声，判定**不执行**并明报
  `not run`，不许把"没触发"当通过（协议 §5.1）。
- 跨内核子系统的操作是"有补偿恢复的 saga"，不承诺原子；恢复失败要保留现场并报告。

### 3.2 实验事实（引用时必须带限定）

- **旗舰矩阵**（`evidence/p2/flagship-matrix-20261023.txt`，60k rps 开环 redis、SLO 5ms、
  20 block、seed 20261024、配对 block bootstrap 10000 次）：
  C(fixed expert) vs A0(fair) goodput **+1.62% [+1.53,+1.82]（20 胜 0 负）**、SET +1.28%；
  p99 **−47.9%**；D(adaptive) vs A0 +1.51%；**A1(只观测不挂载) −0.82%**（观测栈本身是净成本）；
  C vs A2(静态 CPUWeight 倾斜) **+1.90%** ⇒ 收益不是普通优先级倾斜能解释的；
  D vs C 在 SET 上 **−0.27%** 且每块切换 1 次 ⇒ 这条负载上自动切换没赚回自己的空窗；
  BG 相对进度 0.997–1.001（前台收益没饿死后台）；**阈值敏感性：2ms 处 C/D 无优势甚至略负**。
  限定：单机、单负载、单 SLO 设定；原始逐请求件（5.8 GB）留在 SP3 未入库。
- **class 路由是实测零结果**：同块配对 `Cc−C = −0.01% [−0.29,+0.24]`（胜负 10/10）、
  `Dc−D = −0.18% [−0.45,−0.02]`。结论：`spec.targets[].class` 是**契约**（可声明/可审计/可撤销），
  **不是性能开关**。
- **门控行为已量化、价值未测出**：注入越界场景下 D 每轮 25 次 `slo denied`，切换推迟到
  注入撤掉后（≈52s），而阈值不可 bind 的 Dng ≈12s 就切 ⇒ **门把动作推迟约 40s，是延迟器不是否决器**。
  代价在能测的区间≈0–30 个请求（上界）；过载区间机器**双稳**、CI 跨 0 ⇒ **该区间不可测**，
  不是"没差别"。
- **场景覆盖**：quiet / noisy-cpu / noisy-mixed / phase-change / mixed-foreground 均有真机时间线。
  例：phase-change 中 A0 mix 相 p99 4–5ms、累计超预算 0.71%，D ≤1.2ms、0.02%；
  mixed-foreground 中 A0 联合达标 0/3（预算更紧那个只交付 77%），D 2/3。
  限定：mixed-foreground 缺 `D-no-class` 对照 ⇒ 不能归因给 class 分离；跨机 **UNSUPPORTED**。
- **自动 apply 的代价**：每次切换留下 **303–665ms** 无策略空窗；空窗内 1ms 周期唤醒的 p99
  从 1.2–2.0ms 恶化到 13.2–16.1ms。抑制三层各自被单独证明能成为决定门。默认仍关闭。

## 4. 已知的硬天花板（省得重复踩）

**内核行为**（都在 SP3 `6.6.0-schedpilot-sp3` 实测）：

- 第二次 struct_ops 注册被 `EBUSY` 拒绝 ⇒ "存活期间被顶替"不可构造，顶替检测只有 unit 级证据。
- **CPU 下线会直接注销调度器**（`unregistered from the main kernel`；`hotplug_seq` 变、
  `enable_seq` 不变）⇒ 热插拔是策略生命周期事件，v2 的行为是检出并回退，不是扛住。
- `scx_enable()` 先让 `state` 可读、**最后**才递增 `scx_enable_seq` ⇒ 必须等计数器发布，
  否则 verify 误判（这条曾造成 7 次验收里 2 次失败，根因判断曾写错并已在证据中更正）。
- 亲和性受限任务被别的 CPU 从共享 DSQ 拉走时会被**静默改投全局 DSQ**，只有它自己那个 idle CPU
  能取回而无人唤醒 ⇒ 30s 看门狗以 `runnable task stall` 摘除调度器。修复：
  `nr_cpus_allowed==1` 直投本机 local DSQ + `SCX_KICK_IDLE`。**不能声称 stall 类缺陷已穷尽。**
- LAT 份额实际由**片长比**决定（`lat_slice=comp_slice×pct/(100−pct)`）；`lat_budget_pct` 只从上界限；
  记账必须用真实墙钟时长，否则 throttle 永不触发。
- 崩溃/异常退出的执行服务留下的 pinned map 只有**同实例重启**会扫；换 state 目录就无人回收。

**测量能力**：静息 p99 1.7ms 主要是 **idle 退出延迟**（96 个 1ms 睡眠者把它压到 0.23ms）；
1ms 周期探针的 p99 对 CPU 争抢**不敏感**（争抢下 2.5–4.3ms 而 goodput 掉到 1/3）；
**BG 进度在 CPU 争抢下反而升高** ⇒ `BG_PROGRESS_FLOOR` 对这类伤害不响；
同状态 8 窗 p99 极差/均值 46%（而声明预算 5%）⇒ p99 类约束目前不足以驱动自动判定。

**环境**：唯一验收级主机是 SP3；SP4 的 `/sys/fs/cgroup` 是 tmpfs（cgroup v1）且无 PSI ⇒
跨机验证只能记 UNSUPPORTED。旗舰一次约 3.7 小时、5.8 GB 原始件。矩阵与验收各自有 flock 串行锁。

## 7. 工程约定（踩过才写下来的）

- 远端操作：先查 `git status`/diff/实际生效文件与备份；用暂存目录做**哈希一致**校验后再覆盖；
  覆盖前把原件备份到 `/root/epv2-backup-<日期>/`。
- 不要把代码塞进 ssh 引号里；补丁写成文件传过去执行。Windows 侧提交前要 `sed -i 's/\r$//'`。
- 长任务用 `setsid nohup … < /dev/null &`；等结束用 `flock` 锁文件或 marker，
  **不要用 `pkill -f <模式>`**（会自匹配，已犯过三次）。给长驻子进程 `9>&-`，否则它继承锁的 fd。
- 正在跑的脚本不要边跑边改；`$$` 与 `$BASHPID` 在 cgroup 放置上不等价。
- schema 里整数字段不能给浮点；helper 自己有参数下限（越界会被 helper 拒，测的就是 helper 而不是被测方）。
- 只允许特权执行服务写控制 map/cgroup/TC；实验脚本注入"越权写"是**故障注入**，必须在证据里点名，
  且不能留下第二个长期写者。参考 daemon `schedpilotd` 与 v2 必须互斥运行。
- 缺能力就写 UNSUPPORTED/SKIP，禁止用 PASS 遮盖；失败的轮次归档而不是删掉。
