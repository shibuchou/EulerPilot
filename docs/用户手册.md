## 1. 文档背景

EulerPilot v2 是面向 openEuler 的资源管控 Agent(赛题 proj2)。它通过声明式
策略管理 sched_ext 调度器与 cgroup 资源,并提供负载观测、SLO 门控与事件驱动
防护。系统的安装与构建由《部署文档》完成;本手册面向已经部署好的环境,说明
日常使用:如何启动服务、编写与提交策略、读懂状态输出、运行演示、排查问题。

系统的使用模型一句话概括:启动执行服务后,一切写操作通过 `ep` CLI 提交声明式
策略完成;系统负责验证、生效、监控与回退;用户随时可以查询完整状态。

## 2. 快速开始

最快了解系统的方式是运行演示(约 6 分钟,自动完成八步时间线):

```bash
bash scripts/demo_sp3.sh /root/epv2-build/ep-executord /root/epv2-build/ep \
  /root/epv2-build/ep-sched-loader /root/epv2-build/ep-evtmon /root/epv2-evidence/demo-run
```

演示依次展示:契约校验、默认调度器基线、策略生效(内核自证)、扰动下的感知链
应答、崩溃恢复、cgroup 权重调整、事件驱动防护(升权与补偿)、干净收尾。每步
输出 `=== [demo] 步骤名 ===` 与 `-- 说明行`,失败时保留现场目录。

手动走一遍最小流程(调度域):

```bash
# 1. 启动执行服务(前台日志可观察;生产用 setsid/nohup)
/root/epv2-build/ep-executord --state-dir /root/run --socket /root/run/executor.sock \
  --skill sched --loader /root/epv2-build/ep-sched-loader --sched-ctl /root/epv2-build/ep-schedctl

# 2. 校验策略(不生效)
ep validate --file policy.json --socket /root/run/executor.sock

# 3. 取租约并生效
ep lease --ttl-ms 600000 --socket /root/run/executor.sock
ep apply --file policy.json --idempotency-key run-001 --ttl-ms 600000 --socket /root/run/executor.sock

# 4. 查看状态 / 回退
ep status --socket /root/run/executor.sock
ep rollback --of <action_id> --transaction <txn> --snapshot <snap> \
  --policy-sha256 <sha> --socket /root/run/executor.sock
```

`action_id`、`transaction`、`snapshot`、`policy_sha256` 取自 apply 返回的 JSON。

## 3. 启动选项

表 1 ep-executord 常用参数

| 参数 | 说明 |
|---|---|
| `--state-dir DIR` | 状态目录(flock、WAL、marker);默认按 uid 分配 |
| `--socket PATH` | 控制 socket 路径;0600,同 uid 限定 |
| `--skill sched\|sched-ref\|cgroup\|mock` | 效果域。sched 为生产路径(FD 传递),sched-ref 为子进程对照 |
| `--loader PATH` / `--sched-ctl PATH` | sched 域的 loader 与 cfg 辅助程序 |
| `--event-arm FILE` | cgroup 域武装事件守卫(见 5.3) |
| `--auto-apply --auto-policy FILE --auto-owner ID` | 自动专家切换,显式开启;抑制参数另有一组 `--auto-*` |

前置条件:调度域要求 `cat /sys/kernel/sched_ext/state` 为 `disabled` 且
`/sys/fs/bpf/eulerpilot-v2` 为空;否则测试与服务按设计拒绝启动。

## 4. CLI 参考

表 2 ep 命令

| 命令 | 读写 | 功能 |
|---|---|---|
| `ep status` | 读 | 实例、世代号、degraded、租约、观测、事件段 |
| `ep validate --file F` | 读 | 策略校验 + 目标解析 + 摘要,dry-run |
| `ep lease --owner O --ttl-ms N` | 写 | 获取租约(写操作前置) |
| `ep apply --file F --idempotency-key K` | 写 | 策略生效(全事务) |
| `ep rollback --of … --transaction … --snapshot … --policy-sha256 …` | 写 | 按原 apply 的凭据回退 |
| `ep features` | 读 | FeatureWindow 快照(各指标带 valid/age) |
| `ep route` | 读 | 当前路由建议(专家档位 + 理由) |
| `ep slo --expert E` | 读 | 门控判定(allowed + code) |
| `ep observe --file F` | 写(仅摄取) | 提交一窗服务观测;不推进世代号 |

所有命令经 Unix socket 单请求单响应,一行 JSON 入、一行 JSON 出。

apply 返回状态集合:`VERIFIED / REJECTED / ROLLED_BACK / DEGRADED /
RECOVERY_REQUIRED`。`REJECTED` 携带 `error.code`(SCHEMA_INVALID / UNSUPPORTED /
PERMISSION_DENIED / TARGET_STALE / OWNERSHIP_CONFLICT / GENERATION_CONFLICT /
DEADLINE_EXCEEDED / SLO_DENIED 等)。

## 5. 策略编写

### 5.1 调度策略(SchedulingPolicy)

```json
{
  "apiVersion": "eulerpilot.io/v1alpha1",
  "kind": "SchedulingPolicy",
  "metadata": {"name": "protect-redis"},
  "spec": {
    "scope": "scheduler-instance",
    "mode": "class",
    "expert": "latency-balanced",
    "source": "human",
    "targets": [
      {"kind": "cgroup", "path": "/sys/fs/cgroup/system.slice/redis.scope",
       "role": "FOREGROUND", "role_source": "explicit", "class": "LAT"}
    ],
    "parameters": {"lat_slice_ns": 1000000, "comp_slice_ns": 4000000,
                   "cache_slice_ns": 4000000, "bg_slice_ns": 2000000,
                   "preempt_threshold_ns": 500000, "bg_vtime_pct": 200,
                   "llc_affinity": false},
    "safety": {"min_dwell_ms": 5000, "max_observation_age_ms": 1000,
               "heartbeat_period_ms": 250, "heartbeat_timeout_ms": 2000,
               "policy_ttl_ms": 900000, "quiet_max_regression_pct": 5,
               "evaluation_min_bg_progress_ratio": 0.5,
               "bg_work_unit": "probe5s", "bg_progress_window_ms": 5000,
               "min_bg_work_units_per_sec": 140, "max_bg_wait_ms": 50,
               "max_foreground_p99_ms": 10,
               "fallback": "verified-safe-profile", "allow_affinity_change": false}
  }
}
```

表 3 关键字段

| 字段 | 说明 |
|---|---|
| targets[].role | FOREGROUND/BACKGROUND/NEUTRAL;BACKGROUND 需显式声明,系统不猜测 |
| targets[].class | 可选 NORMAL/LAT/COMPUTE/CACHE/BG;`class=BG` 必须配 `role=BACKGROUND` |
| parameters | 有界参数;LAT 预算经片长比表达(见设计文档 §8) |
| safety.policy_ttl_ms | 效果硬上限,到期自动回退 |
| safety.max_foreground_p99_ms | 在线前向延迟绝对上限,单窗即判 |

### 5.2 cgroup 策略(CgroupPolicy)

```json
{"apiVersion": "eulerpilot.io/v1alpha1", "kind": "CgroupPolicy",
 "metadata": {"name": "raise-weight"},
 "spec": {"scope": "cgroup-effects", "source": "human",
          "effects": [{"path": "/sys/fs/cgroup/…/scope", "cpu_weight": 300}],
          "safety": {"policy_ttl_ms": 30000}}}
```

### 5.3 事件授权(EventArm)

```json
{"apiVersion": "eulerpilot.io/v1alpha1", "kind": "EventArm",
 "metadata": {"name": "protect-batch"},
 "spec": {"watch": "/sys/fs/cgroup/…/watched.scope",
          "threshold_wait_ms": 5, "sustain_windows": 1, "release_windows": 1,
          "min_interval_ms": 1000, "lease_ttl_ms": 30000,
          "policy_ttl_ms": 120000, "action": {"cpu_weight": 5000}}}
```

启动武装执行服务与泵:

```bash
ep-executord --state-dir … --socket … --skill cgroup --event-arm arm.json
ep-evtmon --socket … --window-ms 5000 --interval-ms 1000
```

行为:被看 cgroup 的唤醒等待连续 `sustain_windows` 窗超过阈值,权重升至
`action.cpu_weight`;连续 `release_windows` 窗回落、TTL 到期或泵停止后补偿回
原值。同路径 cgroup 重建后授权失效,状态报 WATCH_REBUILT,重启并重新武装后
恢复。

## 6. 状态解读

`ep status` 关键字段:

| 字段 | 含义 |
|---|---|
| generation | 已提交的变更计数;回退也推进 |
| degraded | 存在未完成恢复;此时 apply 被拒,先 `transaction.reconcile` |
| lease | 当前租约属主与到期时间 |
| service.* | 服务观测:最新窗口、p99、后台进度、拒绝原因、断供高水位 |
| event.* | 事件链:armed、持续/回落计数、last_hold、观测新鲜度、WATCH_REBUILT |
| last_fallback | 最近一次自动回退的原因 |
| store_warning | 磁盘写失败的历史警示(恢复后仍可见) |

## 7. 故障排查

表 4 速查

| 现象 | 处置 |
|---|---|
| apply 报 SCHED_EXT not idle | `cat /sys/kernel/sched_ext/state`;有调度器在位先由其属主回退;pin 目录非空时同实例重启执行服务回收 |
| apply 报 TARGET_STALE | 目标 cgroup/pid 已消失或重建;修正策略里的路径后重试 |
| apply 报 GENERATION_CONFLICT | 状态已前进;重新 `ep status` 取新世代号 |
| apply 报 RECOVERY_REQUIRED | degraded 状态;执行 `ep reconcile`(或提交 `{"operation":"transaction.reconcile"}`) |
| 事件守卫不动 | 看 status 的 event.last_hold:NONE=泵未起;STALE=泵已停;below threshold=条件未到;WATCH_REBUILT=对象重建 |
| loader 启动即退、日志为空 | 构建缺 `-DEP_LIBBPF_STATIC`;按部署文档第 5 章重配 |
| 新建 cgroup 写 cpu.weight 报 Permission denied | 用 `systemd-run -p CPUWeight=100 --unit X` 创建 scope |
| rollback 报找不到原始事务 | 凭据三件套必须取自 apply 返回值,不可手造 |

## 8. 常见问题

**Q:策略生效后想换成另一档专家?**
先 rollback 当前效果,再 apply 新策略。调度器同时只允许一个,执行服务会在
apply 前检查在位状态。

**Q:自动切换(AutoPilot)怎么开?**
`--auto-apply --auto-policy baseline.json --auto-owner autopilot-v2`,随后
`ep lease --owner autopilot-v2` 把租约交给它。默认关闭;抑制参数(驻留、候选
保持、切换预算)说明见 `--help`。

**Q:观测断供会怎样?**
门控在超过两倍窗口无新观测后拒绝动作(状态报 SERVICE_OBSERVATION_STALE 或
EVENT_OBSERVATION_STALE);已生效的动作由 TTL 兜底回退。断供时长高水位在
status 里保留,恢复后仍可查。

**Q:演示或实验失败留下现场?**
脚本退出码非零时保留输出目录(路径打印在结尾),daemon.log、journal.jsonl 与
block.invalid 可直接定位;现场也是证据的一部分,排查后再清理。
