# 第12轮后的独立核验与继续执行决定

日期：2026-10-21。依据：当前本地源码、SP3历史验收输出、独立本地构建/测试和代码审查。不能把既有6项测试覆盖范围扩大为P1全部退出门槛。

## 1. 三项决定

1. **架构上允许受控自动apply，但当前保持advisory，不立即开启。** 用户显式授权的policy、目标集合、专家白名单、参数上界、lease、最小驻留与停止条件构成执行边界；执行服务仍是唯一写者。无需每次变更再人工确认，但先完成下列P1安全修复与负路径验证。自动控制不能把`source`伪装成`human`绕过门控，不能自动扩张目标或无限续租。
2. **现在适合建立首个本地checkpoint，但应标注P1未收口，不能打P1完成/release标签。** 先保留当前证据与已知缺口，再将每个修复独立提交。不推送、不覆盖旧仓库。当前Windows与WSL Git均没有作者身份；提交需要用户提供姓名/邮箱。
3. **性能比较必须先冻结协议和负载。** 先做pilot验证工具/工作单元/服务指标，再冻结SP3机器、构建、应用配置、CPU预算、BG角色、SLO、随机种子和有效性规则；之后才跑正式矩阵。现有liveness不能引用为性能或公平性结果。

## 2. 当前阶段判定

- P0：已有SP3环境、参考构建与smoke证据；评审内核政策/截止日期尚未给出。
- P1：已具备控制面与真实scx名义闭环，但**尚未通过退出门槛**。身份、失效恢复、FD与helper边界仍有已确认缺口。
- P2：只有主机级FeatureWindow、规则建议、CPU/PSI压力门控和部分BG写入；没有完整workload行为分类→LAT/COMP/CACHE、真实业务SLO反馈和自动apply闭环。
- P3：尚无v2正式性能结论。

旧报告中的“持有pidfd”“TTL自动回退”“崩溃即detach”只证明已有实现及部分路径通过测试，不能解释成所有故障条件下已经成立。
