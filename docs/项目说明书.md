## 2. 项目背景

### 2.1 问题场景

服务器上同时运行多个业务时,CPU 调度策略直接决定前台服务的延迟和后台任务的
进度。默认调度器对所有任务一视同仁,无法区分"延迟敏感的在线服务"和"不着急的
批处理任务";而调度策略的调整在传统内核里意味着改代码、重启甚至换内核。

表 3 痛点与本项目对策

| 现实痛点 | 现有做法的局限 | 本项目的对策 |
|---|---|---|
| 前台延迟与后台吞吐互相拖累 | CFS 只看 nice/cgroup 权重,不看业务角色 | 声明式策略给出角色与运行特征,数据面按类切片与预算 |
| 调度策略调整成本高 | 改内核调度器需重编与重启 | sched_ext 在运行时挂载/卸载 BPF 调度器(struct_ops) |
| 裸用 sched_ext 风险大 | 直接写 map、无人审计、崩了留孤儿调度器 | 唯一特权写者 + 事务 + 读回自证 + 崩溃恢复 |
| 多来源都能改内核 | Agent、脚本、LLM 各写各的,状态不可知 | 所有变更收进同一条 lease/generation/WAL 通道 |
| 性能结论不可信 | 挑好的数字报、失败轮删掉 | 预注册协议 + 配对 bootstrap + 负结果与失败现场全留 |
| 扩展到新资源域容易失控 | 每加一个域就多一个写者 | Skill 生命周期契约,cgroup 域接入未改核心代码 |

sched_ext 提供了内核侧入口,但要安全使用它需要完整控制面:**谁能改、怎么改、
改坏了怎么恢复**。EulerPilot v2 就是这个控制面加上一个自建数据面。

### 2.2 目标落成四条可验收指标

1. **真实闭环**:sched_ext 调度器在 SP3 上真实挂载、验证、回退,内核状态自证;
2. **工程可靠**:唯一特权写者、声明式契约、崩溃可恢复(fail-safe 矩阵 17 条目);
3. **性能可证**:预注册实验协议下的配对统计结论,含负结果与阈值敏感性;
4. **扩展完整**:R5 的 hook → 决策 → 动作 → 恢复 完整链路真机跑通。

## 3. 系统概述

### 3.1 核心能力

表 5 能力清单

| 能力 | 说明 | 入口 | 验证层 |
|---|---|---|---|

| 自动切换 | AutoPilot 在显式开启后按租约动作,三层抑制 | `--auto-apply` 一组参数 | 集成 `integration_lease`/`integration_ttl` |
| 故障恢复 | 17 类故障场景自动回退,残余由内核 map 自证清除 | 内置(监控线程 + 启动 reconcile) | fail-safe 矩阵 |
| 审计与溯源 | 只追加 WAL、逐轮二进制哈希、逐请求原始数据 | `journal.jsonl` / `PROVENANCE.md` | 一键验收包校验 |

### 3.2 工作原理(一段话版)

执行服务 `ep-executord` 启动后独占状态目录(flock)。用户通过 CLI 提交声明式策略
(JSON 文件),策略先过 schema 与语义校验,再由执行服务在租约与世代号保护下走事务
流程:快照当前值 → 写前日志 → 生效 → 读回验证 → 提交。监控线程每秒检查调度器在
位性、租约与 TTL;任何异常触发补偿回退,内核状态由 map 自证清除。事件链在此之上
增加自动通道:BPF 程序在 sched tracepoint 上测量每个 cgroup 的排队等待,只读泵
汇总上报,执行服务依据人工授权的阈值决定是否调整权重。

表 6 端到端流程(一次 apply)

| 步骤 | 执行者 | 产物/断言 |
|---|---|---|
| 1 提交 | `ep apply --file F` | envelope + policy 一行 JSON;`req-*`/`txn-*` 标识 |
| 2 校验 | 执行服务 | schema + 语义(切片关系、TTL/驻留、class⇔role)→ 违规 `REJECTED` |
| 3 授权 | 执行服务 | 租约属主与 fence 检查、`expected_generation` 比对 |
| 4 目标解析 | `TargetBinding` | `O_PATH\|O_NOFOLLOW` FD + kernfs inode、pidfd + starttime |
| 5 快照与日志 | Journal | WAL `PREPARED`(含快照)后 fsync |
| 6 生效 | Skill | sched:loader 挂载 + cfg/class 写入;cgroup:`cpu.weight` 写入 |
| 7 读回验证 | Skill | state/ops/enable_seq 等值判定;cgroup 文件读回 |
| 8 提交 | 执行服务 | WAL `VERIFIED` → `COMMITTED`,世代号 +1 |
| 9 常驻监控 | 监控线程 | 50ms tick;1s 特征/在位(连续 3 次失败才回退)、2s 刷新与自动通道 |
| 10 回退 | 执行服务 | `COMPENSATING` → 撤销 → 读回确认 → `ROLLED_BACK` |

### 3.3 系统构成

三层结构,权限单向递减(详图与设计理由见 `docs/设计文档.md`):

```
┌─ 决策层(默认 advisory)────────────────────────────────┐
│ FeatureWindow(CPU/load/PSI)→ 规则路由 → SLO 门控 → AutoPilot │
│ 服务观测(service.observe)/ 事件观测(event.observe)→ 只能更严 │
└───────────────┬──────────────────────────────────┘
                │ 声明式策略(JSON Schema 契约)
┌───────────────▼──────────────────────────────────┐
│ ep-executord(唯一特权写者)                            │
│ flock 单实例 · lease/fence · generation · append-only WAL │
│ 事务状态机 · 幂等 · 崩溃 reconcile                      │
└───────┬──────────────────────────────────┬───────┘
   sched 调度域                          cgroup 资源域
 自建 loader(ops eulerpilot)             cpu.weight 写读回 +
 link FD 经 SCM_RIGHTS 交执行服务          marker 崩溃恢复 +
 cfg 参数 · class 分类路由                 EventArm 事件守卫
└───────┴──────────────────────────────────┴───────┘
      内核:sched_ext maps / cgroup v2 / raw tracepoints
```

## 5. 功能说明

### 5.1 调度策略管控

策略是 JSON 文档(`design/schemas/scheduling-policy.schema.json`),声明目标、专家
档位、参数与安全约束;执行服务负责校验、生效、验证与回退。

表 13 关键字段与取值

| 字段 | 取值 | 语义 |
|---|---|---|
| `spec.mode` | basic / class / adaptive | adaptive 在 apply 阶段直接拒绝(见 8.2) |
| `spec.expert` | safe-basic / latency-balanced / throughput-balanced / cache-local | 白名单档位,不可自定义 |
| `spec.source` | rule-template / offline-search / human / llm-proposal | 非 human 必须过门控 |
| `spec.targets[]` | 1–64 条,kind=cgroup/pid,role=FOREGROUND/BACKGROUND/NEUTRAL | 角色必须显式声明,系统不猜 |
| `targets[].class` | NORMAL / LAT / COMPUTE / CACHE / BG | `class=BG` 必须配 `role=BACKGROUND` |
| `parameters.*_slice_ns` | 250000–10000000 | LAT 预算 60% 经片长比表达,实测 57.9–58.5% |
| `parameters.bg_vtime_pct` | 50–400 | 后台虚拟时间惩罚 |
| `spec.safety.policy_ttl_ms` | 10000–3600000 | 效果硬上限,到期自动回退 |
| `spec.safety.min_dwell_ms` | 5000–300000 | 切换驻留下限 |
| `spec.safety.max_foreground_p99_ms` | 1–60000(可选) | 在线前向延迟绝对上限,单窗即判 |

写入路径要点:配置写入 pinned map 前快照、写后读回;分类条目按目标身份写入
class map,NORMAL 不写条目(防 PID 复用继承),成员迁出立即撤销并用 `class-get`
读回确认;每刷新周期轮换抽样一条受管条目,纠正越权修改(`evidence/p1/class-drift-20261025.txt`)。

### 5.2 cgroup 资源管控

`CgroupPolicy` 声明 1–8 个 cgroup 的 `cpu.weight`(1–10000)。执行服务按 kind 路由:
cgroup 策略只能打到 `--skill cgroup` 的实例,反之亦然,拒绝时零副作用。

表 14 cgroup 域生命周期

| 阶段 | 行为 | 失败处置 |
|---|---|---|
| validate | 校验字段、路径合法性(拒绝 `.`/`..` 段与重复路径) | `SCHEMA_INVALID` |
| snapshot | 读当前值入快照 | 读不到即 fail-closed,不进入 apply |
| apply | 写 `cpu.weight`(`O_WRONLY\|O_TRUNC`) | 写失败进 COMPENSATING |
| verify | 文件读回与期望值比对 | 不符 → 回退并 `VERIFY_FAILED` |
| marker | `<state-dir>/cgroup-effects.json` 记录原值与动作 ID | marker 写失败则不声称已生效 |
| refresh | 每周期复查,外部改值被纠正并记日志 | 纠正失败 → 自动回退 |
| 崩溃恢复 | 重启时按 marker 恢复原值 | 恢复失败保留现场并 `RECOVERY_REQUIRED` |
| 叠加保护 | 效果在位时拒绝第二次 apply | `REJECTED`,不产生第二写者 |

### 5.3 事件驱动防护(R5 链路)

`sched/events_trace.bpf.c` 挂在 raw tracepoint(`sched_wakeup`/`sched_wakeup_new`/
`sched_switch`/`sched_process_exit`),按 cgroup kernfs id 聚合任务从唤醒到首次运行
的等待;`start_time` 比对排除 PID 复用误配。只读泵 `ep-evtmon` 每窗口排空聚合 map、
把 id 解析回路径并经 `event.observe` 上报,自身不写任何内核或文件状态。

表 15 EventArm 授权字段

| 字段 | 范围 | 含义 |
|---|---|---|
| `spec.watch` | 必须是活 cgroup 目录 | 被观察对象 |
| `threshold_wait_ms` | 1–60000 | 触发等待阈值 |
| `sustain_windows` / `release_windows` | 1–10 | 升权/回落所需连续窗口数 |
| `min_interval_ms` / `lease_ttl_ms` | 1000–3600000 | 动作最小间隔 / 守卫租约 |
| `policy_ttl_ms` | 10000–3600000 | 升权效果硬上限 |
| `action.cpu_weight` | 1–10000 | 升权目标值 |

判定与动作:`EventArm` 判定函数纯化(证据门 NONE/STALE/无事件/低于阈值 → 持续
N 窗超阈 → apply),动作走与人工策略完全相同的事务路径;回落 N 窗、TTL 到期、泵
停止三条路径任一都触发补偿。同路径 cgroup 删除重建会使授权失效(WATCH_REBUILT),
权限不静默转移给新对象。真机六相时间线见 `docs/测试文档.md` 第 4 章。

17 类故障场景构成 fail-safe 矩阵,每类断言三件事:目标进程继续推进、内核状态由

| S03 | adaptive 模式在 apply 阶段被拒(设计上未启用,拒绝即其 fail-safe 形态) |

## 6. 关键设计决策

表 19 决策记录(完整取舍讨论见 `docs/v2_redesign_2026.md` 与 `docs/设计文档.md` 第 8 章)

| 决策 | 备选 | 选择理由与证据 |
|---|---|---|
| 唯一写者架构 | 各组件自行写内核 | 所有变更走同一事务通道,第二写者在结构上无法构造 |
| link FD 经 SCM_RIGHTS 移交 | loader 常驻 | loader 挂载后即退出,执行服务崩溃即分离,不留孤儿调度器 |
| 失效方向不对称 | 写失败一律拒绝操作 | 拆效应永远放行、建新效应要求可持久化审计;盘满时仍能安全回退(S14) |
| BG 与 LAT/COMPUTE/CACHE 正交 | 按 CPU 占用推断角色 | 业务角色来自显式授权,运行特征来自测量;禁止把陌生高 CPU 任务降为 BG |
| 判定顺序 权限→证据→抑制 | 抑制优先 | 顺序本身是契约;抑制排在证据之后,保证"没证据就不动" |
| 观测只能收紧 | 观测可放行 | 测量数据有噪声与断供两种失败模式,放行会把误报变成动作 |
| 比较类判定声明分辨率 | 直接判 | 同状态 p99 窗间噪声 46%,预算 5% 的判定是噪声放大器 |
| `enable_seq` 等值判定 + 发布等待 | 计数器递增即信任 | 内核在 state 可读之后才递增计数器(`kernel/sched/ext.c:5503–5518`),不等发布会误报 |
| 绑核任务直投本机 local DSQ | 唤醒 idle CPU 等拉取 | 6.6 内核把不允许的拉取改投全局 DSQ;修复前 6/6 失败 → 3×90s 零失速 |
| 份额按片长比表达 | 直接写百分比 | 份额由片长比决定,`lat_slice=comp_slice×pct/(100−pct)` 后 60% 预算实测 57.9–58.5% |
| 跨域失败按 saga 处理 | 承诺原子事务 | 内核多子系统之间不存在原子事务;补偿顺序执行,失败保留现场并 `RECOVERY_REQUIRED` |
| 负结果入档 | 只报有利轮次 | 失败轮与作废轮全部保留;A1 成本、@2ms 无优势均写入正文 |

### 8.2 硬边界(不可回避)

- **性能结论的条件**:单机、单负载(Redis)、单 SLO 设定(5ms);阈值敏感性同报
  —— @1ms C GET +2.5%、@2ms 各臂无优势甚至略负、@10ms ≈+0.6%;收益集中在 5ms
  以上的远尾。
- **一次旗舰矩阵约 3.7 小时**,逐请求原始件(约 5.8GB)留在测试机
  `/root/epv2-evidence/`,仓库入库汇总、`comparisons.csv` 与 SHA256SUMS。
- **观测分辨率**:p99 窗间噪声 46%,不能驱动自动判定;敏感度低于噪声的判定明报
  `not run`。
- **内核行为约束**:Linux 同时只允许一个 sched_ext 调度器(第二次注册 EBUSY);
  CPU 下线会注销调度器(参考实现同样如此);切换存在 303–665ms 空窗。
- **stall 类缺陷未穷尽**:17 条目里没有"排队任务卡死"的主动构造,该根因由独立
  实验定位修复,不等同于覆盖。

## 9. 结论与后续工作

### 9.1 结论

1. **赛题 R1–R10 全部达成**,其中 R4/R8 带明示边界、R6 由消融支撑(判定与逐条
   依据见 `docs/ACCEPTANCE_20261025.md`)。
2. 系统价值主张成立且可验证:**自适应能力本身几乎免费**(D 相对 C 统计打平,
   −0.19%),**观测栈有可测成本**(A1 −0.55%~−0.82%,如实披露),**收益来自数据面
   形态而非 class 标签**(B/C/class-routing 三条线互证)。
3. 工程可靠性以矩阵形式证明:17 类故障在冻结交付构建上 17/17,三代构建各跑一轮。
4. 扩展能力以实际接入证明:cgroup 动作域与 eBPF 事件链在**未修改核心事务代码**的
   前提下并入,成为第 7、8 个必测集成项。

## 10. 术语表

表 25 术语

| 术语 | 含义 |
|---|---|
| sched_ext / scx | Linux 6.6 起的 BPF 调度器框架 |
| struct_ops | 用 BPF 程序实现内核接口_ops 结构的机制,调度器经它注册 |
| DSQ | 调度器内的派发队列(deferred scheduling queue) |
| ops `eulerpilot` | 本项目自建调度器的注册名(`/sys/kernel/sched_ext/ops`) |
| lease / fence / generation | 租约(写权限时限)/ 栅栏(过期凭证识别)/ 世代号(已提交变更计数) |
| WAL | 只追加的写前日志(`journal.jsonl`),崩溃后据此 reconcile |
| TargetBinding | 目标身份绑定:`O_PATH` FD + kernfs inode、pidfd + starttime |
| FeatureWindow | 窗口化的主机特征及其有效性/年龄/来源 |
| goodput@SLO | 延迟不超过 SLO 的成功请求数/秒,按逐请求原始数据统计 |
| 块内配对 | 同一实验块内各臂共享初始条件,差值做统计,消除跨块方差 |
| EventArm | 事件驱动动作的人工授权声明 |
| WATCH_REBUILT | 被看 cgroup 重建导致授权失效的状态 |
| UNSUPPORTED / SKIP | 能力缺失与前置条件不满足的如实标注,与 PASS 并列呈现 |
| fail-safe | 任何故障都向"没有策略"的安全方向回退 |
| saga | 跨域变更的补偿式恢复流程,不承诺内核多子系统原子性 |
