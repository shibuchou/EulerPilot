## 1. 文档背景

本仓库是参加 2026 年全国大学生计算机系统能力大赛操作系统设计赛(中西部与华南
区域赛,功能挑战赛道)的参赛项目,选题 proj2《面向 openEuler 的自适应资源管控
Agent》。赛题要求在 openEuler 24.03-LTS-SP3 上构建可扩展的用户态 Agent,感知
workload 特征并按负载动态选择资源策略,重点经由 sched_ext 改善 CPU 调度,并支持
eBPF 扩展连接 cgroup 等资源域。

服务器上同时运行多个业务时,CPU 调度策略直接决定前台服务的延迟和后台任务的
进度。默认调度器对所有任务一视同仁,无法区分"延迟敏感的在线服务"和"不着急的
批处理任务";直接改内核调度器又要求每次调整都重启或重新编译,风险和成本都高。
sched_ext 允许用 BPF 在运行时更换调度器,为动态调度提供了内核侧入口,但安全地
使用它需要完整的控制面:谁能改、怎么改、改坏了怎么恢复。

EulerPilot v2 解决这个问题。它提供一套三层结构:用户态 Agent 负责感知与决策,
特权执行服务作为唯一写者管理所有策略生效,自建 sched_ext 数据面在内核执行调度。
每次策略变更走完整事务(快照、写前日志、写后读回验证),任何故障都向"没有策略"
的安全方向回退。项目的全部结论在真实 SP3 虚拟机上验证,证据文件随仓库提交。

本文是项目的总览文档,覆盖功能、架构、验证结论与适用范围。深入材料见第 10 章
文档索引。

## 2. 系统概述

### 2.1 核心能力

| 能力 | 说明 | 入口 |
|---|---|---|
| 调度策略管控 | 声明式策略驱动 sched_ext 调度器挂载、参数写入、分类路由、验证与回退 | `--skill sched` |
| cgroup 资源管控 | cgroup v2 `cpu.weight` 的快照、写入、读回验证、漂移纠正与崩溃恢复 | `--skill cgroup` |
| 事件驱动防护 | eBPF 采集每 cgroup 的 runnable 等待,超阈值时自动调整权重,条件消除后补偿 | `--event-arm` + `ep-evtmon` |
| 负载感知 | FeatureWindow 窗口化采集 CPU/load/PSI,规则路由给出专家建议 | `ep features` / `ep route` |
| SLO 门控 | 服务观测与事件观测双通道,测量数据只能让门更严 | `ep slo` / `ep observe` |
| 故障恢复 | 租约超时、策略 TTL、进程崩溃、磁盘写满等 17 类故障的自动回退 | 自动 |
| 审计与溯源 | 只追加 WAL、逐轮二进制哈希、逐请求原始数据 | `journal.jsonl` / `PROVENANCE.md` |

### 2.2 工作原理(一段话版)

执行服务 `ep-executord` 启动后独占状态目录(flock)。用户通过 CLI 提交声明式
策略(JSON 文件),策略先过 schema 与语义校验,再由执行服务在租约与世代号保护
下走事务流程:快照当前值 → 写前日志 → 生效 → 读回验证 → 提交。监控线程每秒
检查调度器在位性、租约与 TTL;任何异常触发补偿回退,内核状态由 map 自证清除。
事件链在此之上增加自动通道:BPF 程序在调度器 tracepoint 上测量每个 cgroup 的
排队等待,只读泵汇总上报,执行服务依据人工授权的阈值决定是否调整权重。

### 2.3 主要量化结论

| 指标 | 数值 | 条件 |
|---|---|---|
| 前台服务 goodput 提升 | GET +1.83% [1.38, 2.26],20 块全胜 | 60k rps Redis,SLO 5ms,块内配对 |
| 前台服务 p99 降低 | −39.6%(GET)/ −32.8%(SET) | 同上 |
| 后台任务相对进度 | 0.998–1.006(未受损) | 同上 |
| 事件泵自身开销 | 0.5% 单核,goodput 配对差 −0.010% | 40k rps 负载 |

| 单元测试 | 587 断言全过 | — |

完整性能边界(@2ms 阈值处无优势、单机单负载单 SLO、跨机 UNSUPPORTED)见

## 3. 总体架构

```
┌─ 决策层(默认 advisory)────────────────────────────────┐
│ FeatureWindow(CPU/load/PSI)→ 规则路由 → SLO 门控 → AutoPilot │
│ 服务观测(service.observe)/ 事件观测(event.observe)→ 只能让门更严 │
└───────────────┬──────────────────────────────────┘
                │ 声明式策略(JSON Schema 契约)
┌───────────────▼──────────────────────────────────┐
│ ep-executord(唯一特权写者)                            │
│ flock 单实例 · lease/fence · generation · append-only WAL │
│ 事务状态机 · 幂等 · 崩溃 reconcile                      │
└───────┬──────────────────────────────────┬───────┘
   sched 调度域                          cgroup 资源域
 自建 loader(ops eulerpilot)             cpu.weight 写读回 +
 link FD 经 SCM_RIGHTS 交执行服务          marker 崩溃恢复 +
 cfg 参数 · class 分类路由                 EventArm 事件守卫
└───────┴──────────────────────────────────┴───────┘
      内核:sched_ext maps / cgroup v2 / raw tracepoints
```

## 4. 功能说明

### 4.1 调度策略管控

策略是 JSON 文档(`design/schemas/scheduling-policy.schema.json`),声明目标
(cgroup 或 pid,含业务角色 FOREGROUND/BACKGROUND/NEUTRAL)、专家档位
(safe-basic/latency-balanced/throughput-balanced)、参数(切片、抢占阈值、
背景权重)与安全约束(TTL、驻留时间、后台进度下限)。执行服务把参数写入 BPF
配置 map,把分类写入 class map,并持续刷新:目标身份失效立即撤销对应条目,
配置漂移自动纠正。

### 4.2 cgroup 资源管控

`CgroupPolicy` 声明 1–8 个 cgroup 的 `cpu.weight` 调整。每次写入前快照原值,
写入后从文件读回确认;执行服务存活期间每个刷新周期复查,外部越权修改被纠正;
进程崩溃后由 marker 文件恢复原值。效果在位时拒绝叠加第二次 apply。

### 4.3 事件驱动防护(R5 链路)

`sched/events_trace.bpf.c` 挂在 sched_wakeup/sched_switch 等 tracepoint 上,
测量每个 cgroup 内任务从唤醒到首次运行的等待时间;`ep-evtmon` 每 2 秒汇总
上报。`EventArm` 声明人工授权的规则:被看 cgroup、等待阈值、持续窗口数、
动作权重、TTL。执行服务据此经标准事务路径调整权重,条件消除、TTL 到期或泵
死亡时自动补偿。同路径 cgroup 删除重建会使授权失效(WATCH_REBUILT),权限
不会转移给新对象。

### 4.4 观测与门控

FeatureWindow 按窗口采集主机特征,路由器按阈值给出专家建议(带滞回)。SLO
门控分两半:服务半区读策略声明的延迟上限与后台进度下限,事件半区读泵的
观测;两者都只能拒绝动作。比较类判定先声明分辨率:策略要求的敏感度低于
实测窗间噪声时,判定报告 not run。

### 4.5 故障恢复

17 类故障场景构成 fail-safe 矩阵:进程崩溃、loader 崩溃、租约超时、策略
TTL、非法策略、generation 冲突、双实例、外部改值、成员迁出、磁盘写满、
CPU 热插拔、两步写入中断等。每类场景断言三件事:目标进程继续推进、内核
状态由 map 自证清除、无 pin 残留。三代构建各跑一轮,均 17/17。

## 5. 关键设计决策

表 2 设计决策与理由

| 决策 | 理由 |
|---|---|
| 唯一写者架构 | 所有变更走同一事务通道,第二写者在结构上无法构造 |
| link FD 经 SCM_RIGHTS 移交 | loader 一次性挂载后退出,执行服务崩溃即分离,无孤儿调度器 |
| 失效方向不对称 | 拆除效应永远放行,建立效应要求可持久化审计;磁盘写满时仍能安全回退 |
| BG 与 LAT/COMPUTE/CACHE 正交 | 业务角色来自显式授权,运行特征来自测量;禁止把陌生高 CPU 任务判为后台 |
| 判定顺序 权限→证据→抑制 | 顺序本身是契约;抑制(驻留/候选保持/预算)排在证据之后 |
| 观测分辨率护栏 | p99 窗间噪声实测 46%,超过多数声明的预算;低于噪声的判定不执行 |
| 份额按片长比表达 | LAT 预算 60% 实测 57.9–58.5%,由 `lat_slice=comp_slice×pct/(100−pct)` 精确控制 |

## 7. 适用范围

- 性能结论的条件:单机、单负载(Redis 开环)、单 SLO 设定(5ms);阈值敏感性
  (@1/2/5/10ms)随结果同报。
- 跨机验证为 UNSUPPORTED:备用机 SP4 为 cgroup v1 且无 PSI。
- X 臂(上游 scx 对照)为 UNSUPPORTED:上游主线调度器已全部 Rust 化,目标
  内核高于本机 6.6。
- adaptive 模式、心跳降级、PMU 分类三项在设计上未启用,apply 阶段直接拒绝。

## 8. 术语表

表 4 术语

| 术语 | 含义 |
|---|---|
| sched_ext / scx | Linux 6.6 起的 BPF 调度器框架 |
| DSQ | 调度器内的派发队列 |
| lease / fence / generation | 租约(写权限时限)/栅栏(过期凭证识别)/世代号(变更计数) |
| WAL | 只追加的写前日志,崩溃后据此恢复 |
| goodput@SLO | 延迟不超过 SLO 的成功请求数/秒,按逐请求原始数据统计 |
| EventArm | 事件驱动动作的人工授权声明 |
| UNSUPPORTED | 能力缺失时如实标注,与 PASS/SKIP 并列的判定 |
