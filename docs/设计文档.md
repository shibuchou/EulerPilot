## 1. 文档背景

EulerPilot v2 是面向 openEuler 的资源管控 Agent(赛题 proj2)。它要在真实的
sched_ext 内核上完成"感知 → 决策 → 执行 → 恢复"的闭环,同时保证任何软件故障
都不会把系统留在未知的调度状态里。实现一份策略容易,难的是让策略的每一次生效
都可验证、每一次失效都可恢复、每一次自动化都有边界。

本仓库为此重新设计了控制面:策略全部声明式、写者唯一、变更全事务化、观测只能
收紧动作。本文件记录这套设计的架构、模块、契约、关键流程与设计决策。设计总纲
(含完整取舍讨论)见 `docs/v2_redesign_2026.md`,接口契约见 `design/INTERFACES.md`
与 `docs/p1/ABI_FREEZE.md`;本文是面向评审的浓缩版,结构与实现一一对应。

## 2. 设计目标与约束

表 1 设计目标

| 编号 | 目标 | 验证方式 |
|---|---|---|
| G1 | 策略生效与回退全事务,崩溃后可恢复 | fail-safe 矩阵 17 条目 |
| G2 | 内核状态自证(读回而非推断) | 集成测试断言 map/文件内容 |
| G3 | 自动化动作有三层边界(权限/证据/抑制) | 门控注入实验 |
| G4 | 性能结论可复现 | 预注册矩阵 + 冻结二进制 |
| G5 | 扩展新资源域只需新 Skill,不动核心 | cgroup 域与事件链的实际接入 |

表 2 硬约束

| 约束 | 来源 |
|---|---|
| 主验收系统为 openEuler 24.03-LTS-SP3 | 赛题要求 |
| Linux 同时只允许一个 sched_ext 调度器 | 内核行为(第二次注册返回 EBUSY) |
| 参考调度器 schedpilotd 与本系统互斥运行 | 同上 |
| 策略生成限于声明式白名单,不在线编译内核代码 | 安全边界 |

## 3. 总体架构

三层结构,权限单向递减:

```
决策层(advisory,默认不动作)
  FeatureWindow → 规则路由 → SLO 门控 → AutoPilot(显式开启)
  service.observe / event.observe(观测摄取,只收紧)
        │ 声明式策略(JSON)
执行层(ep-executord,唯一特权写者)
  flock 单实例 · lease/fence · generation · WAL · 事务状态机
        │ Skill 接口(plan/snapshot/apply/verify/rollback/reconcile)
数据层(两个效果域)
  sched:自建 loader + BPF 调度器(ops eulerpilot)
  cgroup:cpu.weight 文件 + 事件 BPF 观测
```

架构规则:

1. 决策层不持特权。Agent、实验脚本、LLM 通道都只能提交策略,由执行层统一校验
   与生效;`source=human` 的策略保留操作员权威,`rule-template`/`event-template`
   各需通过对应门控。
2. 执行层互斥。flock 状态目录、租约三态(无人/他人/自动通道)、世代号防止旧
   请求覆盖新状态。
3. 数据层可验证。调度器在位性由 state/ops/enable_seq 三项联合判定;cgroup 写入
   一律读回;class 撤销由 map 查询确认。

## 4. 模块设计

### 4.1 执行服务(src/executor/)

| 组件 | 职责 |
|---|---|
| Ownership | flock、租约、fence、世代号的持久化(state.json) |
| Journal | 只追加 WAL,每次 append 后 fsync;撕裂尾行启动时截断 |
| 事务状态机 | PREPARED→APPLYING→VERIFYING→VERIFIED→COMMITTED;失败进 COMPENSATING→ROLLED_BACK 或 RECOVERY_REQUIRED |
| 监控线程 | 1s 特征采样、2s 自动通道评估、1s 在位性探测(连续 3 次失败才回退)、TTL/租约检查 |
| shutdown | 收到停止信号先补偿回退再退出,pin 由自己清理 |

### 4.2 调度 Skill(src/skills/sched_skill.cpp + sched/)

loader 进程完成 struct_ops 注册后,把 link fd 经 SCM_RIGHTS(带 CLOEXEC)
交给执行服务并退出;此后调度器的生命周期归执行服务所有。配置参数由短命
`ep-schedctl` 写入 pinned map,写前快照、写后读回。分类条目按目标身份写入
class map:NORMAL 不写条目(防 PID 复用继承),类变化就地重设,成员迁出即撤销
并读回确认。每刷新周期轮换抽样一条受管条目,纠正越权修改。

### 4.3 cgroup Skill(src/skills/cgroup_skill.cpp)

每次 apply 前写 marker 文件记录原值与动作 ID;写入后读回(`O_TRUNC` 必需,短
值覆盖长值会留残尾);刷新周期复查并纠正漂移;崩溃后由 marker 恢复;效果在位
时拒绝叠加 apply。

### 4.4 事件链(sched/events_trace.bpf.c + src/evtmon/)

BPF 程序挂在 raw tracepoint(sched_wakeup/sched_wakeup_new/sched_switch/
sched_process_exit),按 kernfs id 聚合每个 cgroup 的唤醒等待;start_time 比对
排除 PID 复用误配。泵 `ep-evtmon` 每窗口排空聚合 map、把 id 解析回路径、经
`event.observe` 上报;自身只读(0.5% 单核)。执行服务的守卫消费新窗口,维护
持续/回落计数,判定函数纯化(`event_guard_decide`),动作走标准 apply/rollback。

### 4.5 核心逻辑(src/core/)

策略校验(schema + 语义:切片关系、TTL/驻留、目标重叠、class⇔role 一致性)、
FeatureWindow 窗口聚合、规则路由(阈值 + 5s 滞回)、SloGate(服务半区 + 宿主
半区 + 分辨率护栏)、AutoPilot(驻留/候选保持/切换预算三层抑制)。

## 6. 关键流程

### 6.1 策略生效(policy.apply)

```
CLI 提交(envelope + policy)
→ schema/语义校验 → 租约/fence/世代号检查 → 非人工来源过门控
→ probe → plan → resolve_targets(pidfd/cgroup FD 捕获身份)
→ WAL: PREPARED(快照) → APPLYING → skill.apply
→ WAL: VERIFYING → skill.verify(内核读回)
→ WAL: VERIFIED → COMMITTED(世代号 +1)
任一步失败 → COMPENSATING → skill.rollback → 读回确认 → ROLLED_BACK
```

### 6.2 事件守卫(监控线程,2s 周期)

```
新窗口? → 定位 watch 条目(path+kernfs id 双匹配)
→ 租约(arm 属主)→ 在位效应归属检查 → 纯判定函数
  未生效:证据门(NONE/STALE/无事件/低于阈值)→ 持续 N 窗超阈 → apply
  已生效:回落 N 窗 → rollback;watch 消失/重建 → rollback
→ 动作走 6.1 同一条事务路径;TTL 是效果时长的硬上限
```

### 6.3 崩溃恢复(重启)

```
init → flock → journal 尾行修复 → recover_orphan(扫 pin/marker,撤销无主效应)
→ reconcile 未完成事务 → degraded 判定 → 监控线程启动
```

## 7. 安全与权限模型

表 4 权限层次

| 层 | 持有 | 边界 |
|---|---|---|
| 决策层 | 无特权 | 只能提交策略;观测摄取不推进世代号 |
| 执行层 | BPF/cgroup 写权限 | socket 0600 + SO_PEERCRED 校验同 uid |
| 数据层 | 内核 | 所有写入读回自证 |

自动化边界三例:AutoPilot 需要显式 `--auto-apply` 且租约交给指定属主;事件
event-template 策略只能由武装 arm 的属主租约 + 新鲜观测放行;cgroup 效果在位时
拒绝叠加。跨域失败按 saga 处理:补偿顺序执行,补偿失败保留现场并报
RECOVERY_REQUIRED。

## 8. 设计决策记录

表 5 决策记录(按时间)

| 决策 | 备选 | 选择理由 |
|---|---|---|
| enable_seq 等值判定 + 发布等待 | 计数器递增即信任 | 内核在 state 可读之后才递增计数器(`kernel/sched/ext.c:5503–5518`),不等发布会误报 changed |
| 绑核任务直投本机 local DSQ | 唤醒 idle CPU | 6.6 内核把不允许的拉取改投全局 DSQ,只有本机 CPU 能取回;实测 6/6 摘除 → 3×90s 零失速 |
| LAT 份额用片长比表达 | 直接写百分比 | 份额由片长比决定,`lat_slice=comp_slice×pct/(100−pct)` 后 60% 预算实测 57.9–58.5% |
| 观测只能收紧 | 观测可放行 | 测量数据有噪声与断供两种失败模式,放行会把误报变成动作 |
| 比较类判定声明分辨率 | 直接判 | 同状态 p99 窗间噪声 46%,预算 5% 的判定是噪声放大器 |
| 泵死亡 = 门冻结 | 泵死亡忽略 | 断供后世界的状态未知,冻结 + TTL 兜底保持安全侧 |

## 9. 与参考工作的关系

SchedPilot 的 BPF 数据面与实验方法按 GPL-2.0 派生迁移(`sched/`,逐文件哈希
见 `PROVENANCE.md`);控制面、执行服务、CLI、事件链为本项目实现。专家路由、
SLO 门控思想来自公开文献(`docs/research/sources.md`),本项目的增量在约束链、
发布一致性与实测闭环。EulerPilot(v1)的 Skill 与审计思路保留,代码未复用。
